WHAT THIS ADDS

  "Forgotten your password?" on the sign-in card. An investor types their
  address, gets an emailed link, chooses a new password, and is signed
  in. No password is ever emailed and nothing is read down a telephone.

  And, for the phone-call case, Settings -> Users -> Edit now has
  "Email them a reset link". Administrators only.

THE RULES IT ENFORCES

  It never says whether an address has an account — the same sentence
  either way, and about the same length of time either way, because a
  reply that returns in 4ms for a miss and 400ms for a hit answers the
  question just as clearly as words would.

  The token is not stored. Only its SHA-256, for the same reason a
  password is only stored as a hash.

  One hour, one use. Asking again retires the previous link, so nobody
  clicks a dead link out of an older email.

  Completing a reset ends every other session, clears the
  must-change-password flag, AND lifts the fifteen-minute sign-in
  lockout — without that last one, somebody who did exactly what they
  were told would still be locked out.

  A suspended account is not let back in by remembering its password.

  A dead link says so on arrival, not after a password has been chosen
  and typed twice.

DEPLOY
  Copy over, commit, push. Render rebuilds. Hard-refresh; the footer
  should read 2026-09-10b. No new environment variables — APP_URL and
  RESEND_API_KEY are already set on your service, and the feature needs
  exactly those.

BEFORE YOU TELL ANYONE ABOUT IT
